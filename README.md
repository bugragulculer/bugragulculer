## What I build

I like working at the intersection of **engineering, product, and design**.

My favorite problems usually involve:

* turning messy workflows into simple products
* designing systems that can grow without becoming fragile
* building polished web and mobile experiences
* creating reusable component and design systems
* using AI as part of the product *and* the development workflow
* shipping quickly without treating the first version as the final version

## How I work

```text
Understand the problem
        ↓
Model the system
        ↓
Design the smallest useful version
        ↓
Build the foundations carefully
        ↓
Ship
        ↓
Observe real usage
        ↓
Iterate
```

I care a lot about the part between **"it works"** and **"this feels good to use."**

## Principles

> **Build systems, not piles of features.**

A few things I try to optimize for:

* **Clarity over cleverness**
* **Strong foundations over premature abstraction**
* **Product thinking inside engineering decisions**
* **Small feedback loops**
* **Interfaces that explain themselves**
* **Learning from shipped software instead of chasing perfect first versions**
